# Strict Parse

## Intuition

Panicking is a decision about who can fix the failure. When the input is generated by the program itself, no caller can recover meaningfully — but the payload should still be a full error.

## Approach

1. Call `strconv.Atoi`.
2. Wrap the failure with the quoted input.
3. Panic with the wrapper; return the value otherwise.

## Solution

```go
n, err := strconv.Atoi(s)
if err != nil {
	panic(fmt.Errorf("parse %q: %w", s, err))
}
return n
```

## Walkthrough

The recovered payload is an `error`, so `errors.Is` reaches `strconv.ErrSyntax` through both the `%w` wrapper and `strconv`'s own `*NumError`.

## Pitfalls

- Panicking with a plain string, losing the sentinel.
- Panicking with `err.Error()` instead of `err`.
- Returning an error as well as panicking, confusing the contract.
